# מה זה Steady State - ולמה מערכות נופלות כשמתכננים רק אליו

Steady State הוא המצב שבו המערכת כבר "רצה יפה".
העומס מוכר, ה-cache חם, התורים יציבים, והמדדים נראים טוב.

זה המצב שבו הכי נעים למדוד ביצועים.
וגם המצב שבו הכי קל לטעות בתכנון.

## מה זה בעצם Steady State

Steady State הוא מצב עבודה יציב ומתמשך:

- קצב הבקשות קבוע יחסית
- המשאבים מנוצלים באופן צפוי
- Latency לא קופץ
- אין הפתעות חריגות

## למה קל להישבות בקסמו של Steady State

כי שם הכול מסתדר:

- הגרפים חלקים
- הממוצעים יפים
- ה-P95 סביר
- המערכת "מרגישה בשליטה"

רוב הבדיקות, המצגות והאופטימיזציות
נעשות בדיוק שם.

הבעיה:
העולם האמיתי לא חי רק ב-Steady State.

## מה Steady State מסתיר

Steady State מסתיר את הרגעים החשובים באמת:

- עלייה חדה בעומס
- Restart של רכיב
- Cache שנופל
- שינוי בדפוס תעבורה

כלומר -
את הרגעים שבהם המערכת נדרשת להסתגל, לא רק לעבוד.

מערכת שמתוכננת רק ל-Steady State
נראית מצוינת -
עד שהיא יוצאת ממנו.

## Steady State ≠ בריאות מערכתית

מערכת יכולה להיות מושלמת ב-Steady State
ועדיין להיות שברירית מאוד.

למה?

כי בריאות מערכתית נמדדת ביכולת לעבור בין מצבים:

- מ-Cold ל-Warm
- מ-עומס נמוך לגבוה
- מתקלות חזרה ליציבות

לא בזמן שבו הכול כבר הסתדר.

## המשל: שיוט באוויר

מטוס מתוכנן לא רק לשיוט חלק.
הוא מתוכנן להמראה, לנחיתה, ולרוחות לא צפויות.

שיוט הוא המצב הארוך ביותר -
אבל לא המסוכן ביותר.

כך גם במערכות.

## איך מתכננים מעבר ל-Steady State

מערכות יציבות לא שואלות רק
"איך זה עובד כשהכול רגיל?"
אלא גם:

- איך נכנסים ל-Steady State?
- כמה זמן לוקח להגיע אליו?
- מה קורה כשיוצאים ממנו?
- האם אפשר לחזור אליו בלי דרמה?

Steady State הוא יעד -
לא הנחת יסוד.

## סיכום

Steady State הוא תמונה יפה של מערכת רגועה.
אבל הוא רק פרק אחד בסיפור.

מערכות חזקות לא נמדדות
בכמה טוב הן מתפקדות כשהכול כבר יציב -
אלא בכמה אלגנטי הן מגיעות לשם,
יוצאות משם,
וחוזרות שוב.
