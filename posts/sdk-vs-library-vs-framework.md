# SDK vs Library vs Framework - מה ההבדל?

## מה ההבדל בין SDK ל-Framework?

שני המונחים נמצאים כמעט בכל פרויקט תוכנה, אבל הם משרתים מטרות שונות מאוד.

### Framework - מסגרת עבודה שמכתיבה איך לכתוב את הקוד

Framework הוא "שלד" מוכתב מראש.
הוא קובע איך האפליקציה בנויה:

- איפה כותבים קוד
- איך מחלקים מחלקות
- מתי הפונקציות שלך מופעלות
- מהו הזרם הלוגי (Flow) של התוכנית

Framework משתמש בגישה של Inversion of Control:
הוא זה שקורא לקוד שלך - ולא להפך.

**דוגמאות:**
React, Django, Angular, FastAPI

Framework הוא למעשה מערכת שעליה את בונה.

### SDK - ערכת כלים לשימוש במערכת קיימת

לעומת זאת, SDK לא מכתיב איך לבנות את האפליקציה שלך.
הוא רק מספק את הכלים לדבר עם מערכת אחרת:

- פונקציות מוכנות
- עטיפות נוחות
- ספריות + תיעוד
- כלים לבדיקות ואינטגרציה

SDK נועד לשרת אותך -
לא לנהל את האפליקציה שלך.

**דוגמאות:**
AWS SDK, OpenAI SDK, NVIDIA TensorRT SDK, Android SDK

ב-SDK:
את קוראת לכלים → את שולטת בזרימה.

ב-Framework:
המסגרת קוראת לקוד שלך → הזרימה מוכתבת מראש.

## Library vs SDK - מה ההבדל?

אף ששניהם "קוד מוכן לשימוש", הם שונים במהותם.

### Library - אוסף פונקציות שמוסיפות יכולת מסוימת

ספרייה (Library) היא אוסף של פונקציות או מחלקות שאת יכולה להשתמש בהן מתי שתרצי.

היא לא מגדירה:

- איך לכתוב קוד
- איך לבנות פרויקט
- איך להשתמש בה בצורה מסוימת

היא פשוט מספקת יכולות ספציפיות.

**דוגמאות:**
NumPy, OpenCV, Requests, Matplotlib

### SDK - ספרייה + תשתיות + כלים + תיעוד

SDK כולל לעיתים ספרייה, אבל הוא הרבה יותר גדול:

- דוגמאות קוד
- כלי פיתוח
- סימולטורים
- תיעוד מלא
- רכיבי Build
- קונפיגורציות
- כלים לתקשורת עם מערכת מורכבת
- ולעיתים גם Framework קטן שמעל הספרייה

Library היא לבנה אחת.
SDK הוא ערכת בנייה שלמה.

## סיכום בשלושה משפטים

- **Library** = אוסף פונקציות שאת יכולה לקרוא אליהן.
- **SDK** = כל מה שצריך בשביל לעבוד עם מערכת - ספריות + כלים + תיעוד.
- **Framework** = מסגרת שמכתיבה איך האפליקציה שלך בנויה ופועלת.
